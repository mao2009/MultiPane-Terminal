# 省メモリ性能評価計画

未測定の数値を製品性能として表記しない。現段階の目標（例：起動時35MB、タブ増分8MB）は**仮説であり採用条件に固定しない**。

## 比較環境
同一Windows実機・ディスプレイ解像度・DPI・フォント・ターミナルサイズ・シェル・スクロールバック上限・GPU設定で測る。OS版、CPU、RAM、GPU、電源プラン、候補のcommit/tagを記録。各シナリオ3回以上で中央値・ばらつきを記載する。

## シナリオ
1. 起動直後：1ウィンドウ1ペイン1タブ
2. 4タブ、8タブ（同一シェル）
3. 4ペイン・8タブ：表示と非表示の両方
4. 大量出力、長いANSIシーケンス、Unicode/IME
5. バックグラウンドでの出力継続と切替
6. 1時間アイドル
7. タブ開閉100回、ペイン再分割100回
8. WSL利用（Windows側とWSL側のメモリを分離記録）

## 計測対象
- ホストプロセスの Private Bytes / Working Set / Commit
- ConPTY関連プロセス（conhost/OpenConsole等）のメモリ
- 子シェル及び起動したアプリケーションのメモリ
- プロセスツリー総量（共有ページの重複計上に注意）
- GPUメモリ、CPU使用率、起動時間、非表示タブの出力正当性
- タブ1件増加による限界増分（総量差分）

## 判定基準
要件への適合が前提。総メモリ、増分、CPU、フリーズ/出力欠損、ライセンス、保守性、フォーク改修量を並記し、トレードオフをADRとして説明する。

## 結果テンプレート
候補 / version / 環境 / シナリオ / ホストPrivate Bytes / ConPTY / 子プロセス / GPU / CPU / 試行回数 / 中央値 / 再現手順 / 注記。
