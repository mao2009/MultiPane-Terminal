# 設計原則（技術選定前）

## 優先順位
1. 既存製品で実現可能なら作らない
2. 実利用時の**総メモリ使用量**とアイドルCPU負荷を小さくする
3. 既存OSSの実装を最大限再利用する（ライセンス・更新追従・セキュリティを検証）
4. セッションの信頼性とWindows互換性（ConPTY/IME/Unicode/VT）
5. 保守性と開発工数

## UI不変条件
- ルートは再帰的分割ツリー。内部ノードは左右/上下分割、葉はペイン。
- ペインには独立したタブグループがある。タブは別のペインに移動可能。
- セッションはタブ切替・ペインサイズ変更では終了しない。
- 非表示タブのPTY出力は停止させない。描画は抑制できる。
- タブを閉じる場合、子プロセスの終了方針を明確化し誤終了を避ける。

## 実装境界
- PTY / VT解析 / フォント処理 / レンダリングは原則既存OSSから流用する。
- 既存ホストをフォークする場合、そのペイン/タブUI改修だけで足りるか最初に調べる。
- 新規ホストが必要なときのみWin32等を検討。言語はC++/Rust/C#等から実測と依存関係で選ぶ。
- プロセス分離、GPUバックエンド、ランタイムは「軽そう」という印象では決めない。

## プライバシー
テレメトリー、アカウント連携、不要な常駐プロセスは実装しない。設定はローカル保存とする。

## 保留
ライセンス、最低Windowsビルド、セッション復元、SSH統合、ショートカット、描画方式、NativeAOT可否、各数値目標は調査後にADRで決定。
